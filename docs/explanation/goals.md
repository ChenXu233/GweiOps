# 目标

> 状态:现行 | 日期:2026-11-02
> 读者:所有人
> 口径:本文只写目标与由目标推出的硬约束。怎么实现见 [变更单元契约](change-unit-contract.md),边界与取舍见 [平台架构](platform-architecture.md)。

GweiOps 是 AI 驱动的运维智能体平台:把外部信号变成外部世界里已经验证过的改变。名字取自《易经》第 63、64 卦——既济(事已成)、未济(事未成)。

## 四条目标

1. **半夜不吵醒人。** 信号来自 Issue、监控告警、CVE 源、扫描器;系统在夜间把信号变成已验证的外部改变,人早上只做判断,不负责复原现场。
2. **一个人也敢打。** 几百人才敢运维的系统,几个人甚至一个人就敢打,包括功能更新与金丝雀发布。
3. **只绑定,不自建。** 不实现监控、不实现金丝雀,也不自建 Git 与 CI;把已有的运维基建接进来,高度自动化并保留人在回路。插件可替换,社区能改自己需要的地方。
4. **闭环四段。** 触发 → 诊断修复 → 部署报告 → 学习,或回滚。

## 由目标推出的硬约束

| 约束 | 来自哪条目标 | 怎么判 |
| --- | --- | --- |
| 平台不制造可逆性,只登记并兑现它 | 2、3 | 撤销由下游执行;核心不出现运维动作调用 |
| 人在回路,不在闸门 | 1、2 | 可逆变更先做后报;不可逆变更先报后做 |
| 撤销窗口必须覆盖人的响应时延 | 1 | 窗口 < 8h 视为不可逆,阻断等人 |
| 平台不假设与下游同机 | 3 | 单元带 binding,提供者声明 binding |
| 能力按 (租户, 目标) 解析 | 3 | 选不到直接抛,不跨目标回退 |

## 不在目标里

自建 Git、CI、监控、金丝雀;通用编程助手;存储指标;替客户写业务代码。
